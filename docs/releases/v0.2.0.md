v0.2.0 is a development/public-preview release of the logs-only ServiceNow Event Management exporter.

- Add opt-in `sha256_v1` generated message keys. `legacy` remains the default. The new format changes generated identities; plan migration, close or drain old-key alerts, and account for queued or replayed events before switching. Fitting explicit keys are unchanged; oversized explicit keys under `sha256_v1` are permanent mapping errors.
- Capture one admission timestamp for untimed records before queueing, keeping event time stable across queue delay and retries. This timestamp does not establish delivery order.
- Preserve otherwise mappable records when exporter metadata exceeds the `additional_info` budget by using a bounded reduction envelope. `otel.servicenow.additional_info.metadata_reduced` is reserved; optional metadata and original severity text may be omitted on this path.
- Add bounded mapping diagnostics counted per affected record occurrence and mapping attempt. Retries count again; these metrics are neither unique-loss totals nor delivery acknowledgments.
- Saturate representable numeric `Retry-After` values beyond `time.Duration` range at the maximum; Collector retry budgets still apply. Recognized interruptions while reading successful 2xx responses can retry a POST ServiceNow already processed, risking duplicate event rows or Business Rule effects.
- Treat JSON `null` in recognized 2xx error fields as absent while retaining HTTP status and non-null response failure checks.
- Reject fractional and non-finite severity doubles before conversion and apply the existing severity mapping and fallback.
- Maintain optional upstream-to-logs recipes for metrics-derived breach events and selected trace exceptions, plus an optional native log-context overlay. Native metrics and traces export remain unsupported; the recipes do not define alert recovery or lifecycle behavior.

Compatibility and validation: the module minimum is Go `1.25.0`; Go `1.25.7` is the selected build toolchain following a metrics-distribution linker issue seen with `1.25.0`. Collector component/tool modules remain `v0.153.0`, and stable modules remain `v1.59.0`. The tag workflow runs `make verify` on the tagged commit. ServiceNow evidence is historical and dated in the [compatibility matrix](https://github.com/pocket-grimoire-guild/otelcol-exporter-servicenow-event-management/blob/v0.2.0/docs/compatibility.md); it does not establish current live-instance, alert-lifecycle, or production validation. Customer-like non-PDI validation, tested maximum batch/request sizes, and direct instance mTLS remain open.
